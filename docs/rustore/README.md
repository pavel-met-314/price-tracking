# Путь в RuStore: что подготовлено и что делает человек

Здесь лежат материалы публикации. Код к магазину подготовирован ровно в одном месте: сборка
`release` подписывается ключом из секретов CI, а `debug` — ключом из репозитория.

## Что уже сделано в репозитории

* `app/build.gradle.kts` — конфигурация подписи `release` из переменных окружения
  (`OTSLED_RELEASE_STORE_FILE`, `OTSLED_RELEASE_STORE_PASSWORD`, `OTSLED_RELEASE_KEY_ALIAS`,
  `OTSLED_RELEASE_KEY_PASSWORD`) либо из локального `gradle.properties`. Ключа нет — `assembleRelease`
  выпускает неподписанный APK и не падает: debug-прогоны и тесты от ключа не зависят.
* `.github/workflows/ci.yml` — шаг `Build release APK (нужен для публикации в RuStore)`: если секрет
  `OTSLED_RELEASE_KEYSTORE_BASE64` заполнен, CI декодирует ключ, собирает `assembleRelease` и кладёт в
  релиз `app-release.apk` плюс закреплённую за версией копию `app-release-<версия>.apk`. Секретов нет —
  шаг ничего не делает.
* `app/src/release/AndroidManifest.xml` — в магазинной сборке убрано разрешение
  `REQUEST_INSTALL_PACKAGES`: приложение обновляет себя только в отладочных сборках, и в release-APK
  права на установку быть не должно (иначе это вопрос модератора, на который приходится отвечать).
* `docs/privacy-policy.md` — политика: никаких персональных данных, два сетевых адреса, локальное
  хранение. Её надо опубликовать по постоянному адресу (см. ниже).
* `docs/rustore/icon-512.png` — иконка 512×512, без альфа-канала.

## Ключ и секреты: как завести с телефона

Ключ уже сгенерирован и лежит в `keys/` (папка в `.gitignore`, в историю не попадает):
`otsled-release.keystore`, его же base64 в `otsled-release.keystore.base64.txt` и пароли в
`passwords.txt`. Агент не может заводить секреты репозитория — GitHub отдаёт
`403 Resource not accessible by integration`, поэтому четыре значения вставляешь ты сам.

1. GitHub → репозиторий → **Settings → Secrets and variables → Actions → New repository secret**
   (на телефоне — меню ⋯ → Settings; нужен экран «Secrets and variables», а не «Environments»).
2. Четыре секрета, имена ровно такие:

   | Имя | Откуда значение |
   | --- | --- |
   | `OTSLED_RELEASE_KEYSTORE_BASE64` | содержимое `keys/otsled-release.keystore.base64.txt`, целиком одной строкой |
   | `OTSLED_RELEASE_STORE_PASSWORD` | строка `storePassword` из `keys/passwords.txt` |
   | `OTSLED_RELEASE_KEY_ALIAS` | `otsled` |
   | `OTSLED_RELEASE_KEY_PASSWORD` | строка `keyPassword` из `keys/passwords.txt` |

3. Проверка без нового коммита: **Actions → «CI» → Run workflow → Run workflow** (workflow
   поддерживает `workflow_dispatch`). В прогоне шаг `Build release APK` должен сообщить
   `release: подпись на месте`, а в релизе `latest` появиться `app-release.apk` и
   `app-release-<версия>.apk`.
4. Скачай `keys/` к себе (файлы + пароли) и храни в менеджере паролей. Потом папку можно удалить:
   CI читает ключ из секретов, а не из рабочего дерева.

Свой ключ (рекомендуется перед первой публикацией, пока в магазине пусто — смена подписи тогда
ничего не ломает):

```bash
keytool -genkeypair -v -keystore otsled-release.keystore -alias otsled \
  -keyalg RSA -keysize 2048 -validity 10000 -storetype PKCS12 \
  -dname "CN=<имя разработчика>, O=<он же>, C=FI"
base64 -w0 otsled-release.keystore    # macOS: base64 -i файл | tr -d '\n'
```

и теми же четырьмя секретами замени значения. Тип хранилища, если он не PKCS12 (старый JKS),
передаётся переменной `OTSLED_RELEASE_STORE_TYPE`.

## Что заходит в магазин

Файл: `https://github.com/pavel-met-314/price-tracking/releases/download/latest/app-release.apk`
(или `app-release-<версия>.apk` — то же самое, но его не перезапишет следующий прогон).

| Поле | Значение |
| --- | --- |
| Название | «Отслеживание цен Allure Parfum» (или своё — пока совпадает с `app_name`, иначе иконка и название в APK разойдутся) |
| Категория | Покупки → Косметика и украшения (подойдёт и «Утилиты») |
| Краткое описание | Цены на парфюмерию: следите за скидками на 40+ позиций и получайте уведомление, когда цена упала до цели |
| Полное описание | см. ниже, три абзаца |
| Иконка | `icon-512.png` |
| Скриншоты | 2–5 штук, портрет 9:16, от 1080×1920 (см. «Как снять скриншоты») |
| Политика конфиденциальности | публичная ссылка на `docs/privacy-policy.md` |
| Тестовый доступ | не нужен: аккаунта нет, приложение работает сразу |
| Возрастная категория | 12+ (отслеживается товар категории «парфюмерия», пользовательского контента нет) |
| Платежи, реклама, аналитика | нет ничего из перечисленного |

Полное описание — по-человечески и без обещаний, которых в приложении нет:

> Приложение следит за ценой выбранных товаров в интернет-магазине Allure Parfum: вы добавляете
> позицию поиском по названию или ссылкой, при желании задаёте целевую цену, дальше приложение само
> проверяет страницу и сообщает, когда цена упала. История цен сохраняется, на карточке товара
> доступен график. Список можно сортировать и фильтровать: ниже цели, упала цена, есть проблемы, без
> цены; ненужное убирается в архив вместо удаления. Работает без аккаунта и интернета «в один
> момент»: проверки идут по расписанию или фоном, уведомления локальные. Данные хранятся только на
> устройстве.

## Ссылка на политику

RuStore требует постоянный адрес. Самый дешёвый способ для публичного репозитория:

```
https://raw.githubusercontent.com/pavel-met-314/price-tracking/main/docs/privacy-policy.md
```

Raw-ссылка отдаёт текст с `Content-Type: text/plain`, читалка в магазине такой адрес принимает; если
модератор попросит «человеческую страницу» — включите GitHub Pages для `docs/` и дайте ссылку на
`.../privacy-policy.html` (для этого рядом нужен `index.html`, добавим по запросу).

## Как снять скриншоты

Три кадра закрывают всё, что видит модератор:

1. список товаров с фильтром (видно, что данные реальные и что список не пустой);
2. карточка товара с графиком цены;
3. «Настройки» с журналом проверок.

Снимается парой кнопок: клавиша питания + громкость вниз. Обрезка не нужна, системная строка
допустима. Присылайте PNG мне — разложу по `docs/rustore/screenshots/` под именами `01-list.png`,
`02-detail.png`, `03-settings.png` и проверю размеры перед загрузкой.

## Типичные причины отказа именно у такого приложения

* **«Приложение обновляется вне магазина»** — у нас обновляющая себя часть в release-сборке
  выключена и разрешение на установку вырезано из манифеста; это же можно указать в комментарии
  модератору.
* **Название/иконка не совпадают с тем, что внутри APK** — держим `app_name` и название в магазине
  одними и теми же.
* **Не указано, откуда берутся данные** — в описании и в политике назван магазин и адрес; это то же
  самое, что требует модератор.
* **`versionCode` не вырос** — CI берёт его из `app/build.gradle.kts`; каждый публикуемый прогон должен
  нести больший номер, чем уже установленный в магазине.
* **Потерянного ключа не бывает**: подпись release меняется — обновление для существующих установок
  невозможно, только удаление и установка заново.
